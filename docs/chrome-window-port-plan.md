## 最小影响原则

保留上游全部现有架构和功能，以旧分支作为行为与局部实现的参考，不作为文件合并来源。优先复用上游窗口交接、结果缓存、分组维护和关闭保护。确需增加的跨窗口编排集中在独立模块，通过少量入口接入。

不迁入旧分支的大范围设置界面删改、不恢复旧 AppTabBar 和 useTabDrag，不撤销上游插件、MCP、分屏、标签分组/排序、启动流程等更新。

## 已处理的兼容点（不是 Git 文本冲突）

1. **窗口身份不同**：新增 `dbx-tab-*` / `dbxWorkspace` 工作窗口；保留上游 `detached-tab-*` 路径。新工作窗口只与 `main` 和同类工作窗口交接，插件浮窗、旧式独立标签窗及预览窗不参与。
2. **交接与失败恢复**：扩展上游 handoff 序列化而不放宽旧式独立窗口接口。目标持久化后向 Rust 注册表原子提交，源窗口确认后才移除；超时取消、迟到提交和 IPC 响应丢失按同一终态裁决。交接期间暂时冻结输入，避免快照之后发生编辑。
3. **分屏归属**：接收通过现有 `adoptDetachedTab`、`moveTabToGroup`，移除通过 `removeTabAfterDetachedReady`；不恢复旧分支的扁平 tabs 修改方式。
4. **多窗口持久化**：后端按实际调用窗口隔离快照。主窗口下次启动恢复已消失子窗口的标签，遵循上游恢复设置；主窗口保存成功后才清理恢复来源。子窗口刷新只读自己的快照，不读 main 的旧 localStorage。
5. **应用级行为**：子窗口不重复执行自动备份调度、WebDAV 自动上传、更新检查、外部文件事件消费和独立窗口回收；预览页加载不会重置 main 的 frontend-ready 状态。
6. **关闭安全**：子窗口复用上游未保存提示；主窗口退出前要求子窗口持久化，并拒绝存在未完成任务或无法持久化编辑的退出。子窗口不会被提升为 main。

## 用户行为与边界

- 开启预览时支持完整多标签工作窗口、拖出新窗口、窗口间往返、插入提示和转移菜单。
- 关闭预览时回到上游既有行为，不移除其独立窗口能力。
- 本次不实现主窗口继任：始终保留固定 main，主窗口关闭遵循上游退出/托盘设置。继任方案待本次移植完成后单独评估。
- 上游插件浮窗不参与标签转移与主窗口继任。
- 原有预览开关默认值先保持不变；不顺便更改其他设置默认值。
- 有尚未提交的数据网格修改时禁止转移，需先保存或放弃，避免迁移未被 handoff 序列化的编辑状态。
- Windows 支持原生鼠标释放监测和透明预览；其他平台不声明具有相同的原生拖出能力，指定窗口菜单使用通用交接路径。
- 主窗口选择退出仍是退出应用，不是把 main 转交给另一窗口；选择托盘行为仍遵循上游设置。

### 2026-10-13：拖到窗口时判断落点

- 松手位置命中已有 DBX 工作窗口后，由目标窗口在自己的 DOM 中检测是否落在标签栏，并通过窗口事件返回结果；坐标按目标窗口位置和缩放因子换算，不用源窗口的 DOM 猜测目标标签栏。
- 明确命中标签栏才合并到目标窗口；目标明确回复未命中标签栏时，新建子窗口。这让“拖进窗口但没落到标签栏”表示创建新窗口，而不是拒绝接收。
- 目标未就绪、通信超时或命中检测出错时保留源标签并提示目标不可用，不把通信故障误判为用户要新建窗口。
- 在源窗口自身的当前标签组内容区释放、且没有命中标签栏时，也新建子窗口；其他标签组仍保留原有组间移动语义，避免覆盖分屏操作。
- 新增回归覆盖已有窗口标签栏命中、已有窗口/源窗口非标签栏释放、目标未就绪四种分支；未涉及主窗口继任逻辑。
