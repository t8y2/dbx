<Callout type="info">权限管理仅适用于 DBX Web 版（浏览器访问或 Docker 部署）。桌面版仍是单用户全权模式，本页的任何设置都不会影响桌面版。</Callout>

## 概述

DBX Web 内置多用户 RBAC（基于角色的访问控制）体系。管理员创建账号，并为每个账号分配一个或多个角色。角色决定两件事：

1. **功能权限** —— 该用户可以使用哪些应用功能（工具栏操作、右键菜单及其对应的接口）。
2. **数据范围** —— 该用户可以看到哪些连接与连接分组，以及其中哪些连接允许写入。

## 用户与管理员

- 首个账号由管理员在首次启动的初始化向导中创建，自动拥有管理员标志。
- 管理员可以在管理界面中新增账号、重置密码、禁用或删除账号。
- 管理员不受任何限制：永远可见全部连接，永远通过所有权限检查。权限体系只对非管理员账号生效。

## 角色与功能权限

角色持有一组功能权限 key，当前共 9 项：

| 权限 | 控制范围 |
| --- | --- |
| 管理连接 | 创建、编辑、删除数据库连接与连接分组 |
| 数据传输 | 在数据库、模式、表之间迁移结构与数据 |
| 执行 SQL 文件 | 上传 SQL 脚本文件并批量执行 |
| 结构对比 | 比对两个数据库或模式之间的对象结构差异 |
| 数据对比 | 比对两个表之间的数据差异 |
| 备份与恢复 | 数据库备份与恢复任务 |
| 导入数据 | 将 CSV/Excel 等数据文件导入数据库表 |
| 导出数据 | 将查询结果或表数据导出为文件 |
| MCP | 通过 MCP 协议向外部 AI 工具开放数据库连接与查询能力 |

说明：

- 在角色编辑界面，鼠标悬停在任一权限上都会显示该权限的用途说明。
- 新建角色时，默认勾选**管理连接**和**执行 SQL 文件**。
- 查询不是功能权限：可见的连接即可读，能否写入由下方「写入更新」按连接控制。
- 取消勾选**管理连接**会弹出确认框提醒，因为取消后该用户将无法新建连接、连接数据库和执行脚本。

## 数据范围（可见性）

角色编辑界面以连接树形式展示每个分组和连接的两套独立状态：

- **可见** —— 该分组/连接出现在侧边栏，其数据可读。
- **写入更新** —— 该连接允许执行修改类操作。

规则：

- 授权跟随分组：勾选分组即授予其下全部后代连接（除非单独取消），分组上的「写入更新」对该分组下所有连接生效。
- 可见性默认拒绝：数据范围为空的角色不授予任何资源，用户将看不到任何连接（包括未分组连接）。
- 桌面版始终显示全部连接，完全不感知数据范围。

## 写入更新（默认只读）

每个可见连接**默认只读**，即使它已经可见：

- SQL 写语句（按语句分类的 `INSERT`/`UPDATE`/`DELETE`/DDL）会被拒绝并返回 `403`，界面给出中文提示。
- 写操作类端点同样被拦截，例如 Redis 命令执行、MongoDB 文档增删改、Elasticsearch/Meilisearch 文档与索引写入、HBase 行操作、MQ 管理等。
- 只有勾选了**写入更新**的连接（直接勾选或通过祖先分组继承）才允许修改数据。

由此可以安全地构造只读账号：只授予可见性、不授予写入；需要可写时勾选对应连接的一个复选框即可。

## 双层拦截机制

权限检查分两层协同工作：

1. **界面层** —— 缺少对应权限时，工具栏按钮和右键菜单项会被隐藏，用户根本看不到不可用的操作。
2. **后端层** —— 所有受保护的 API 都在服务端校验。绕过界面直接调用接口仍会收到 `403`，返回 `permission_denied`、`connection_forbidden`、`query_write_forbidden` 等机器可读错误码，界面会把这些错误码显示为本地化的中英文提示。

隐藏入口只是体验优化，不是安全边界——后端的接口校验才是最终裁决。

## 黑名单

管理界面还提供 IP 黑名单，可在认证之前直接拦截指定客户端。它是独立的安全补充手段，不能替代角色体系。
