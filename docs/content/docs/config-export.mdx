<Callout type="info">Export your database connections with encrypted passwords (AES-256-GCM). Securely migrate between machines. Encrypted export remains the default.</Callout>

<Callout type="warn">This exports DBX connection configuration, not business database schema or data, and it is not a database backup. Use [Database Export](/en/docs/database-export) or [Database Backup](/en/docs/database-backup) for database contents.</Callout>

## Export

<Steps>
<Step>
    ### Start Export

    Click the **Export** button in the sidebar header.
  </Step>
<Step>
    ### Select Connections

    Choose one or more connections. All connections are selected by default. Only the selected connections, their sidebar groups and ordering, and referenced tunnel profiles are exported.
  </Step>
<Step>
    ### Choose Export Protection

    Enter a passphrase to encrypt your passwords. For a one-time migration in a trusted environment, you may instead choose **Export without encryption** and confirm the warning. Plaintext export excludes credentials by default. To retain them, explicitly check **Include passwords and other credentials (plaintext)** before confirming.
  </Step>
<Step>
    ### Save File

    Choose a save location. The exported file contains only the selected connections, their related layout, and referenced tunnel profiles. Encrypted export is recommended.
  </Step>
</Steps>

## Import

<Steps>
<Step>
    ### Start Import

    Click the **Import** button in the sidebar header.
  </Step>
<Step>
    ### Select File and Decrypt

    Select the exported file. DBX automatically detects encrypted and plain configuration files. Encrypted files ask for the passphrase first so DBX can decrypt and preview them without writing anything yet.
  </Step>
<Step>
    ### Select Connections

    Choose which connections from the file to import. All connections are selected by default.
  </Step>
<Step>
    ### Done

    Only the selected connections are imported, with passwords restored. Deduplicated by name + host + port. Sidebar groups and ordering for the selected connections can still be applied after import.
  </Step>
</Steps>

## CLI and MCP imports

For a local DBX export, use `dbx connections import --file connections.json --json` to preview, then add `--yes` after reviewing the counts and warnings. MCP provides `dbx_import_connections` with `file_path`; omit `confirmed` for preview, and set `confirmed: true` only after approval. Credentials remain in the protected local file, never in the tool arguments or result.

These interfaces perform an add-only atomic import, including supported connection settings, referenced tunnel profiles, and sidebar groups/order with remapped IDs. They skip existing connections only when normalized name, host, port, database type, and database all match; connections with equal names but different endpoints/types/databases remain separate, and existing settings or credentials are never overwritten. Input files are limited to 16 MiB and must be owner-only on Unix. Import is local-only, normally requires the existing initialized encrypted store, and respects MCP policy. CLI additionally offers explicit `--initialize` for a completely empty profile; it refuses existing connections or legacy credentials and creates no key during preview. For encrypted exports, add CLI `--passphrase-file passphrase.txt` or MCP `passphrase_file`, pointing to a separate owner-only UTF-8 file. Never supply a literal passphrase in command arguments or tool calls. See [CLI import](/en/docs/cli#import-a-dbx-connection-bundle).

## Security

- Passwords are encrypted using **AES-256-GCM** with **PBKDF2** key derivation
- Without the passphrase, an encrypted file cannot be decrypted
- Plaintext export excludes passwords and other credentials by default. The optional **Include passwords and other credentials (plaintext)** setting writes them in readable form; use it only for temporary migration in a trusted environment, protect the file, and delete it when finished
- The export file is standard JSON, transferable via USB drive, cloud storage, etc.
- DBX stores ordinary connection fields separately from secrets such as database passwords, SSH passwords, SSH key passphrases, and full connection strings. Encrypted export protects the combined data; plaintext export writes those secrets as readable JSON only when explicitly selected for that export. The choice resets when cancelling or leaving the plaintext confirmation, and after a completed export.
- Treat the passphrase like a secret. Anyone with both the export file and passphrase can restore the saved connections.

## Backward Compatibility

Import automatically detects encrypted or plain configuration files. It also supports plain JSON files from older versions (without passwords) and raw connection config arrays.

## What Is Included

| Item                                                                   | Included                                                              |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Connection name, type, host, port, database, color                     | Yes                                                                   |
| URL parameters, SSL, SSH, proxy, visible database settings             | Yes                                                                   |
| Database password, SSH password, SSH key passphrase, connection string | Encrypted exports: yes. Plaintext exports: only with explicit credential opt-in |
| Vendor JDBC driver JAR files                                           | No; reinstall or re-import drivers on the target machine              |
| Sidebar groups and ordering for selected connections                   | Yes; choose whether to apply them after import                        |
| Saved SQL and UI/editor settings                                       | No; use [Cloud Sync](/en/docs/cloud-sync) to migrate them             |

For JDBC migrations, export the connection settings here, then use [JDBC Plugin](/en/docs/plugins) to install the plugin and import driver JARs on the destination machine.
