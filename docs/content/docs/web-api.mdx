## Base URL

By default, DBX Web listens on port `4224`:

```text
http://localhost:4224
```

When deployed behind a reverse-proxy subpath, set `DBX_PUBLIC_BASE_PATH` and prefix every route. For example, with `/dbx`:

```text
https://example.com/dbx/api/auth/check
```

All API routes are under `/api`.

## Authentication

Protected routes require a session cookie named `dbx_session`. Accounts gate login only: connections and settings are stored server-side and stay shared across all signed-in accounts.

### Check Auth State

```http
GET /api/auth/check
```

Example response:

```json
{
  "authenticated": false,
  "required": true,
  "setup_required": false
}
```

| Field | Meaning |
| --- | --- |
| `required` | Password protection is enabled |
| `setup_required` | First-run account setup is still needed |
| `authenticated` | Current request already has a valid session |
| `username` | Signed-in account name, present only when authenticated |
| `is_admin` | Signed-in account may manage user accounts |

### First-Run Setup

```http
POST /api/auth/setup
Content-Type: application/json

{
  "username": "admin",
  "password": "your-password"
}
```

Setup creates the first user account and is only accepted while no account exists. The first account becomes the admin; accounts created later through user management are regular accounts.

### Login

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "your-password"
}
```

`username` is optional and defaults to `admin`, which keeps older password-only clients working.

On success, the response sets `Set-Cookie: dbx_session=...`. Reuse that cookie on later requests.

Five consecutive login failures on one account from one source IP trigger an approximately 60-second lockout for that account and address only — other accounts and other addresses stay unaffected. Failed logins to unknown usernames count toward the lockout and every attempt runs the same password-hash verification, so neither the response nor its timing reveals whether an account exists. Sessions live in the current Web process and require login again after restart; deployers can additionally mark the cookie `Secure` with `DBX_COOKIE_SECURE=1` and expire idle sessions with `DBX_SESSION_IDLE_TIMEOUT_MINUTES`. The cookie is `HttpOnly`, uses `SameSite=Lax`, and follows `DBX_PUBLIC_BASE_PATH` for its path.

### Change Password

```http
POST /api/auth/change-password
Content-Type: application/json
Cookie: dbx_session=...

{
  "old_password": "current-password",
  "new_password": "new-password"
}
```

Any signed-in account can change its own password by proving the old one; the request can only target the session's own account (admins reset other accounts through user management instead). New passwords must be at least 8 characters, and failed old-password attempts share the login lockout. On success, all other sessions of that account are revoked; the session that made the change stays signed in.

### Logout

```http
POST /api/auth/logout
Cookie: dbx_session=...
```

### User Management

Only admin accounts can manage users — the first account created during setup is the admin, and accounts configured via the `DBX_PASSWORD`/`DBX_USERNAME` environment variables always count as admins. Admins may grant admin rights when creating an account (`is_admin: true`). Env-provided accounts are listed with `managedByEnv: true` and cannot be modified through the API; a database account shadowed by a same-named env account is not listed, since the env account is authoritative for that username. Passwords set here must be at least 8 characters. Changing a password revokes the account's other sessions; resetting another account's password revokes all of its sessions.

```http
GET /api/auth/users
Cookie: dbx_session=...
```

```json
[
  { "id": 1, "username": "admin", "createdAt": 1754800000000, "managedByEnv": false, "isAdmin": true }
]
```

```http
POST /api/auth/users
Content-Type: application/json
Cookie: dbx_session=...

{
  "username": "alice",
  "password": "her-password",
  "is_admin": false
}
```

`is_admin` is optional and defaults to `false`; admins may pass `true` to create another admin.

```http
POST /api/auth/users/{id}/password
Content-Type: application/json
Cookie: dbx_session=...

{
  "password": "new-password"
}
```

```http
DELETE /api/auth/users/{id}
Cookie: dbx_session=...
```

Deleting your own account, the last remaining account, or the last remaining admin account is rejected (the admin guard does not apply while an env-provisioned account exists).

### Environment Variables

| Variable | Purpose |
| --- | --- |
| `DBX_PASSWORD` | Pre-configure a login account at container startup (password) |
| `DBX_USERNAME` | Username for the `DBX_PASSWORD` account; defaults to `admin` |
| `DBX_DISABLE_PASSWORD=1` | Disable password protection entirely |
| `DBX_COOKIE_SECURE` | `1`/`true` marks session cookies `Secure`; use with HTTPS deployments |
| `DBX_SESSION_IDLE_TIMEOUT_MINUTES` | Expire sessions idle longer than this many minutes; unset or `0` keeps sessions until logout or restart. Open SSE streams and WebSocket connections count as activity, and expired sessions are swept in the background once a minute |
| `DBX_PORT` | Change the listen port (default `4224`) |
| `DBX_DATA_DIR` | Data directory containing `dbx.db` |
| `DBX_PUBLIC_BASE_PATH` | Serve DBX under a subpath such as `/dbx` |
| `DBX_MAX_UPLOAD_MB` | Override the general request and uploaded-file limit; default 1024 MB. Multipart routes reserve fixed protocol overhead (set at least `4096` for a 4 GiB file) |
| `DBX_AGENT_DIR` | Override the Web Agent/driver directory; defaults to `agents` under the data directory |
| `DBX_STATIC_DIR` | Override the Web static asset directory |

## Request Format

- Field naming follows each Rust request type. Some bodies use `camelCase`, while connection configuration still contains `snake_case`; do not apply one naming convention to the whole API.
- `GET` query parameters commonly use `snake_case`, such as `connection_id`, but the current route implementation remains authoritative.
- Errors usually return JSON with an `error` field and an HTTP status code.
- Long-running export, import, transfer, SQL-file, and AI operations commonly use a start request plus SSE progress and cancel/download routes rather than one synchronous response.

Only the data-grid extractor currently exposes a tested, scoped OpenAPI document at `/api/query/data-grid-extractor-openapi.json`. It does not cover the complete DBX Web API or version the other routes.

## Connection APIs

### List Connections

```http
GET /api/connection/list
Cookie: dbx_session=...
```

Returns saved connection profiles. Secrets such as passwords are stored separately from the returned JSON.

### Save Connections

```http
POST /api/connection/save
Content-Type: application/json
Cookie: dbx_session=...

{
  "configs": [
    {
      "name": "local-mysql",
      "db_type": "mysql",
      "host": "127.0.0.1",
      "port": 3306,
      "username": "root",
      "database": "app"
    }
  ]
}
```

### Test Connection

```http
POST /api/connection/test
Content-Type: application/json

{
  "config": {
    "name": "temp",
    "db_type": "mysql",
    "host": "127.0.0.1",
    "port": 3306,
    "username": "root",
    "database": "app"
  }
}
```

### Connect

Most data APIs expect the target connection to be active first.

```http
POST /api/connection/connect
Content-Type: application/json

{
  "config": {
    "id": "connection-id",
    "name": "local-mysql",
    "db_type": "mysql",
    "host": "127.0.0.1",
    "port": 3306,
    "username": "root",
    "database": "app"
  }
}
```

### Check Health

```http
POST /api/connection/check-health
Content-Type: application/json

{
  "connectionId": "connection-id"
}
```

## Schema APIs

### List Tables

```http
GET /api/schema/tables?connection_id=CONNECTION_ID&database=app&schema=
Cookie: dbx_session=...
```

### List Columns

```http
GET /api/schema/columns?connection_id=CONNECTION_ID&database=app&schema=&table=users
Cookie: dbx_session=...
```

Other schema routes include:

- `/api/schema/databases`
- `/api/schema/schemas`
- `/api/schema/indexes`
- `/api/schema/foreign-keys`
- `/api/schema/ddl`

## SQL Query APIs

### Execute One Statement

```http
POST /api/query/execute
Content-Type: application/json

{
  "connectionId": "connection-id",
  "database": "app",
  "sql": "select id, name from users limit 10"
}
```

Example response shape:

```json
{
  "columns": ["id", "name"],
  "rows": [[1, "Ada"], [2, "Lin"]]
}
```

Related routes:

| Route | Purpose |
| --- | --- |
| `/api/query/execute-multi` | Execute multiple result sets in one request |
| `/api/query/execute-batch` | Execute a list of statements |
| `/api/query/cancel` | Cancel a running query |
| `/api/query/build-table-select-sql` | Build a table browse query |

## Redis APIs

## MCP and CLI Integration

For automation, these packages are usually easier to maintain than calling the Web API directly:

- MCP: [@dbx-app/mcp-server](/en/docs/mcp)
- CLI: [@dbx-app/cli](/en/docs/cli)

When MCP runs against a deployed Web instance, set:

```json
{
  "env": {
    "DBX_WEB_URL": "http://localhost:4224",
    "DBX_WEB_PASSWORD": "your-password"
  }
}
```

The MCP server handles login and session cookies for you.

CLI supports the same `DBX_WEB_URL` and `DBX_WEB_PASSWORD` variables. Both integrations reuse server-side connections, drivers, read-only protection, production protection, and database privileges, making them easier to maintain across DBX upgrades than copied internal route payloads.

## Writes, Safety, and File Boundaries

- API authentication proves only that the request belongs to a logged-in session; it does not replace database privileges
- Query, import, and transfer paths continue to enforce connection read-only protection, while production and SQL-risk policy apply in their corresponding core paths
- Browser-selected table-import and SQL files are uploaded into server temporary storage, not read from arbitrary client paths
- Web exports create a temporary server file, return it through a download route, and then clean it up
- Reverse proxies should preserve cookies and SSE streaming, allow appropriate long-running timeouts, and limit public exposure
