DBX 是一个开源、轻量的数据库与数据基础设施工作台。它把连接管理、对象浏览、SQL 编辑、数据修改、结构工具、专项控制台和自动化入口放在同一个工作区中，支持 70+ 种数据库及数据系统。

DBX 不会强行把所有系统都抽象成 SQL 数据库：关系型数据库使用查询编辑器、数据表格和 Schema 工具；Redis、MongoDB、向量数据库、消息队列、etcd、ZooKeeper、Nacos 等系统则使用更符合其数据模型的专项界面。

<Callout type="info">如果你已经决定开始使用，可以直接阅读 [快速开始](/cn/docs/getting-started)。如果你正在确认某个引擎或功能是否支持，请查看 [数据库支持与功能矩阵](/cn/docs/databases)。</Callout>

## 支持的不只是 SQL 数据库

DBX 的连接选择器按实际工作方式组织数据库和数据系统。不同类别会进入不同的工作区，而不是只显示一个通用查询框。

| 类别 | 代表系统 | DBX 中的主要体验 |
| --- | --- | --- |
| 关系型与兼容协议 | MySQL、PostgreSQL、SQLite、Oracle、SQL Server、达梦、openGauss、GaussDB | SQL 编辑器、数据表格、对象树、表结构、Schema 工具 |
| 分析型与数据仓库 | ClickHouse、Doris、StarRocks、Databricks、Snowflake、Trino、BigQuery | 查询、结果分析、元数据浏览，以及驱动支持的结构和导出能力 |
| 文档、键值与搜索 | MongoDB、Redis、Elasticsearch、Easysearch、Meilisearch、HBase、Cassandra | 文档、键、索引或表族等专项浏览器 |
| 图、向量与 AI 数据 | Neo4j、Qdrant、Milvus、Weaviate、ChromaDB | 图数据库连接，以及向量集合浏览、检索和写入入口 |
| 时序系统 | QuestDB、TDengine、IoTDB、InfluxDB | 时序查询与系统对应的连接、对象和数据视图 |
| 消息队列 | Pulsar、Kafka、RocketMQ、RabbitMQ | Topic、订阅/消费者、消息、监控、权限或策略等能力 |
| 注册与配置中心 | etcd、ZooKeeper、Nacos | Key/ZNode 浏览、集群状态、访问控制、配置与服务管理 |
| 驱动扩展 | JDBCX、自定义 MySQL/PostgreSQL、可选 JDBC 插件 | 使用兼容协议或厂商 JDBC 驱动扩展连接范围 |

具体数据库能使用哪些高级能力，取决于驱动、协议和数据库本身。以 [数据库支持](/cn/docs/databases) 中的功能矩阵为准；专项系统的入口与边界见 [专项工作台](/cn/docs/specialized-workspaces)。

## 一套工作流，多个使用入口

| 入口 | 适合场景 | 能力与边界 |
| --- | --- | --- |
| 桌面版 | 个人日常开发、本地数据库文件、完整工作台 | 提供本地文件、SQL 文件树/SQL 库、桌面 Deep Link 等操作系统集成 |
| Docker / Web | 服务器自托管、远程浏览器访问 | 共享大部分数据库工作流；文件路径指向服务器，部分本地文件和桌面集成功能不可用 |
| CLI | 终端、脚本、CI、Codex 工作流 | 列出连接和 Schema、描述表、执行查询、生成紧凑上下文，并可唤起桌面端打开表 |
| MCP Server | Claude Code、Cursor、Windsurf 等 AI 客户端 | 列出连接、读取结构、执行受策略约束的查询或命令，并可连接本地数据目录或 DBX Web |

桌面版和 Web 版复用同一套 Rust 核心能力，但它们不是所有系统集成上的完全等价替代。选择部署方式时，应同时考虑数据库所在网络、文件位于本机还是服务器，以及是否需要桌面 Deep Link 或本地 SQL 文件管理。

## 从连接到自动化

<Steps>
  <Step>
    ### 建立连接边界

    选择数据库类型，填写认证信息，并按需要配置 TLS、SSH、SOCKS5、HTTP 代理或 HTTP 隧道。为高风险连接启用只读或生产环境保护。

  </Step>
  <Step>
    ### 先理解对象和上下文

    从侧边栏查看数据库、Schema、表、字段、索引、外键和数据库专属对象。陌生数据库可以先使用搜索、对象源码、ER 图或字段血缘建立上下文。

  </Step>
  <Step>
    ### 查询、检查并修改

    在查询编辑器中执行 SQL，或在数据表格、文档/键值浏览器和专项控制台中完成对应操作。DBX 会在可行时展示 SQL 或请求内容，便于执行前审查。

  </Step>
  <Step>
    ### 比较、迁移和复用

    使用 Schema 对比、表导入、数据传输、数据库导出、SQL 文件执行、查询历史和 SQL 库，把一次性操作变成可检查、可复用的流程。

  </Step>
  <Step>
    ### 接入 AI 与自动化

    在应用内使用 AI Ask/Agent，或通过 CLI 和 MCP 把连接、Schema 上下文和查询能力提供给终端脚本与 AI 编程助手。

  </Step>
</Steps>

## 安全模型

DBX 使用多层限制，而不是只依赖一个“危险操作确认”开关：

- **数据库账号权限**始终是最终边界，建议生产环境使用最小权限账号。
- **只读连接**会在核心查询执行路径阻止可识别的写入，并隐藏或禁用多个修改入口。
- **生产环境保护**可以作用于整个连接或指定数据库；检测到写入时，每次都要求新的明确确认。
- **可审查的变更**会在数据编辑、表结构、Schema 对比等流程中尽量先展示 SQL。
- **AI Ask 模式**只生成回答，不执行 SQL；Agent 在生产环境中不会获得自动写入授权，而是把 SQL 放回编辑器供人工检查。
- **MCP 策略**统一管理连接 allowlist 和“只读 / 数据读写 / 完全访问”三档权限，且不能绕过连接只读、生产保护和数据库账号权限。
- **敏感配置**与普通连接 JSON 分开存储；配置导出可使用 AES-GCM 加密。

完整配置和各入口的行为见 [生产环境与写入安全](/cn/docs/production-safety)。

## 需要了解的边界

<Callout type="warn">
  DBX 是数据库工作台，不是托管数据库服务，也不能替代数据库账号权限、审计、备份和变更审批。数据库导出适合轻量备份或迁移，但大型生产库仍应使用数据库原生备份工具。AI 输出、自动生成的 SQL 和跨引擎数据迁移都需要人工审查。
</Callout>

- 高级功能不会对所有数据库强行开放；不可靠的兼容路径会被隐藏或降级。
- Docker/Web 中的本地路径属于服务器文件系统，不是浏览器所在电脑。
- JDBC/Agent 数据库需要相应驱动或运行时，功能范围可能少于原生驱动。
- [Web API](/cn/docs/web-api) 主要服务 DBX Web 和内部集成，不是稳定的公共契约；脚本和 AI 集成优先使用 CLI 或 MCP。
