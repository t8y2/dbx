# MCP 能力分类：实现与验证

## 实现边界

能力页使用「分类导航 → 工具集 → 工具详情」，保持现有 Neutral Modern 主题、shadcn 控件和 Lucide 图标。分类由前端目录元数据决定，不修改后端 API、工具名称或策略结构。

| 分类 | 工具集 ID |
| --- | --- |
| 数据库 | `sql.query`、`sql.session`、`sql.schema`、`redis` |
| Nacos | `nacos.config`、`nacos.service` |
| Consul | `consul.kv`、`consul.service` |
| 消息队列 | `mq` |
| Salesforce | `salesforce` |
| DBX 通用 | `core.discovery`、`workbench`、`admin.connections`、`plugin.router` |
| 其他能力 | 不在上述映射中的工具集 |

插件按真实名称独立展示，带来源和待确认徽标。高级配置提供自定义工具白名单。内置工具、工具集、分类和高级白名单的修改都进入原有策略草稿；插件授权即时保存。插件白名单放行操作明确提示需要应用。

分类批量操作使用完整后端目录，包含筛选隐藏的工具。将 `null`（全部允许）转换成显式名单时，保留全部其他内置工具和插件通配符；显式名单保留已有自定义条目。共享发现位于 DBX 通用，因此关闭数据库分类不会影响其他产品的连接发现。

界面按能力区域实际宽度响应：600px 以下使用分类选择器，600–759px 使用 144px 导航，760px 以上使用 184px 导航。搜索不改变原分类；详情不依赖过滤结果，关闭详情时恢复触发位置，触发元素消失时返回搜索框。

## 桌面验收步骤

1. 打开「设置 → MCP → 能力」。确认默认数据库分类、各分类顺序、实际工具数量和启用数；切换分类后先前草稿仍在。
2. 关闭数据库分类，检查 Nacos、Consul、DBX 通用的启用状态保持原值。取消设置并重新打开，确认内置草稿撤销；再次修改并应用，重新打开应保持修改。
3. 仅开启某个工具，勾选「仅显示已开启」，再执行本分类全部开启；被隐藏的工具也应开启。关闭最后一个工具后停留原分类并显示空状态，导航仍保留。
4. 搜索分类名、工具集名、工具名称/ID、插件名/ID。结果应标明路径与来源，不显示分类批量按钮；点击具体工具直接展开，清空搜索恢复原分类。
5. 在仅显示已开启的搜索结果中打开工具并关闭它。详情应继续显示；关闭详情后，若原结果消失，键盘焦点应返回搜索框。
6. 选择插件，检查总开关、上限、工具集和待确认状态。首次开启和确认新增工具应进入授权流程；保存期间禁用对应控件。模拟保存失败时显示错误且保留旧状态。插件保存成功后取消设置，授权应仍然保留。
7. 如果全局白名单限制插件，点击放行后应看到需要应用的提示；此操作可被取消撤销。高级配置添加自定义条目不能改变其他分类或移除插件通配符。
8. 验证空连接、空插件、作者未开放、发现失败、目录加载失败及刷新/重试。暂无适用连接的内置工具仍可配置；已开启但无可暴露工具的插件保留原因。
9. 在普通设置弹窗和宽页面，分别检查能力区域小于 600px、600–759px、至少 760px 的布局；切换明暗主题，并检查英文和长名称换行、参数局部滚动。
10. 使用 Tab、Enter、Space、Escape 完成分类切换、搜索、开关、详情打开/关闭，确认焦点可见，详情关闭后回到触发按钮或搜索框。

使用隔离样例数据渲染实际 Vue 组件，检查数据库、Nacos、插件授权和搜索状态，以及宽版、紧凑双栏、窄版选择器、明暗主题、中英文、批量空状态、保存失败、工具直达及焦点恢复。样例页不调用真实插件或数据库，临时预览文件在验证后移除。
