# Mongo Compare 与手动同步

功能复用现有 MongoDB 查询、`runCommand`、连接权限及生产环境确认接口，桌面端与 Web 共用实现。

## 使用

1. 右键 MongoDB 数据库或集合，选择 **Mongo 对比与同步**。也可以从工具栏的数据对比工具菜单打开。
2. 分别选择源端、目标端的连接、数据库和集合。支持同一连接内的不同集合，以及不同连接之间的集合。
3. 默认按 `_id` 匹配。业务键或复合键可填写 `customer.id,region`。匹配字段必须唯一且存在。
4. 可为两侧分别填写 JSON / Extended JSON 筛选条件；忽略字段用点路径和逗号分隔，例如 `_id,updatedAt,metadata.debug`。
5. 开始对比后，按相同、内容不同、仅源端、仅目标端或匹配不唯一查看结果。点击匹配键查看两侧完整文档与字段差异；支持 CSV / JSON 导出。
6. 勾选文档后选择同步方向，或使用字段旁的箭头复制单个字段。检查预览中的接收端、操作数量及 MongoDB 命令，点击 **确认并应用更改** 后才写入。

## 保存配置与多集合比较

- 填写顶部的配置名称，点击 **保存 / 重命名**；使用 **另存为新配置** 复制当前设置。选择已保存配置后恢复输入，手动点击开始对比。支持删除配置和未保存更改提示，最多保存 50 个。
- 配置保存在本机应用/Web 浏览器存储中，包含连接 ID、数据库/集合选择、两侧筛选、匹配/忽略字段、读取上限和集合配对；不另存连接凭据、文档结果或同步计划。清理应用数据会清除配置。存储失败会明确提示，不会误报保存成功。
- 勾选 **对比多个集合**，选择两侧数据库，点击 **添加同名配对**，或 **添加配对** 手动指定不同名称的集合。每组可以单独设置匹配字段，留空使用全局默认值；筛选条件、忽略字段和读取上限共用。
- 一次最多比较 100 组，按顺序执行；可取消，单组失败会记录错误并继续下一组。汇总明确区分失败、取消和部分读取，支持 JSON 导出。
- 批量比较只保留统计。点击 **重新读取明细** 后，重新读取该组文档并显示差异；然后勾选文档或字段，手动确认同步。不会仅依据旧汇总批量写库。
- 每组读取前及同步前会检查集合是否仍存在，避免将消失的集合当作空集合。完成或尝试同步后，所有批量汇总标记为需重新比较，因为不同配对可能引用同一个集合。

## 同步语义

- 新增：发送端存在、接收端不存在时复制完整文档，保留 BSON 类型。
- 更新：仅应用实际比较出的字段变化，保留接收端 `_id` 和忽略字段。缺失字段与 `null` 不等价。
- 删除：接收端独有的选中文档将被删除；预览明确列出删除数量和命令。
- 字段复制：仅更新该字段，支持双向复制；数组作为整体比较，顺序有意义。
- 自定义匹配键：相同键的多个文档不会被自动配对，禁止同步。该分组显示两侧匹配数和首个文档。
- 数值：默认区分 Int32 / Int64 / Double / Decimal128；启用数值相等选项后按十进制字符串规范化，避免大整数转成 JavaScript Number 而丢失精度。

## 数据范围与保护

- 默认每侧 10,000 个文档，可调整到 100,000；分批读取，额外探测一条判断是否截断。单侧序列化数据预算为 64 MiB。
- 部分结果不会被标为全量相同，并且禁止同步。请缩小筛选范围或提高上限。
- 只接受驱动返回的 Extended JSON，避免把界面显示字符串误写成日期或 ObjectId。旧驱动缺少此数据时会提示更新。
- 执行前检查全部计划中两侧的文档，再在每条操作前复查。接收端更新/删除附加原文档条件，检测并发变化。匹配检查不受 UI 筛选条件限制，以免漏掉筛选范围外的重复数据。
- 不跨数据库建立事务；遇到失败停止，已完成操作保留。断网后最后一条写入可能已生效，必须重新对比，不能直接重试旧计划。
- 自定义匹配键的计划包含新增文档时，接收端必须有覆盖匹配字段（或其子集）的完整、非稀疏、非部分唯一索引；否则同步会在首次写入前停止。`_id` 匹配直接使用内置唯一索引。索引防止检查与插入之间的并发重复业务键。
- 同步期间不要删除或重建唯一索引。分片集合的 `_id` 跨分片唯一性仍遵循服务器部署约束，DBX 不额外提供跨分片唯一性保证。
- 两侧读取不是同一时刻的事务快照；在数据稳定的时间段比较。同步结果失效后需重新运行对比验证。
- 只读连接不能接收同步。生产环境仍使用 DBX 的统一写入确认流程。
- MongoDB `$expr` 用于匹配和原文档校验，需要 MongoDB 3.6+；本次真实数据库验证使用 MongoDB 7.0.14。
