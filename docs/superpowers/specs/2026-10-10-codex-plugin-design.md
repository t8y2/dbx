## 用户目标与交付方式

在 Codex 中安装 DBX 插件后，能够直接打开 DBX 工作台、管理数据库连接、执行 SQL、浏览编辑数据和使用 MCP，无需安装或启动 DBX 桌面应用，无需手动启动 Web 服务。保留原有 DBX 界面和数据库实现。

在用户 fork `git@github.com:skyfour/dbx.git` 中开发，分支为 `feat/codex-plugin`。交付面向上游 PR；按用户选择跳过 Issue。提交 PR 的时间与范围以实际实现及验证结果为准，不能将未实现能力描述为已交付。

## 架构

```text
Codex
  ├─ 插件 skill → 打开工作台工具 → 返回本地 URL → Codex 内置浏览器面板
  └─ 插件 stdio MCP 入口（原生启动器）
       ├─ 自动启动或复用插件专属 dbx-web 服务
       └─ 使用 rmcp 连接服务的 /mcp，转发工具与资源
                              │
                 同一 dbx-web / AppState
                    ├─ 原有 Web 工作台与 HTTP API
                    ├─ 数据库引擎和现有权限策略
                    └─ 插件专属持久化数据与驱动目录
```

插件包附带当前平台的启动器和包含前端的 `dbx-web`，运行时不依赖本机 Rust、Node、Docker 或桌面 DBX。开发阶段需要 Rust 与现有前端工具链。二进制使用同一次源码构建，不混用不匹配版本。

采用独立的原生启动入口，复用仓库已有 rmcp；不自行编写 JSON-RPC、SSE 或 MCP 会话协议。启动管理放在专属模块内，避免改变桌面启动行为。

## 插件内容和用户流程

- 插件清单、MCP 配置、工作台 skill、图标、许可证及构建产物。
- 工作台工具返回经过校验的 loopback URL；skill 指导 Codex 使用宿主打开面板的能力，不硬编码当前用户的绝对路径。
- 用户第一次进入工作台，在原有界面中设置访问密码、创建连接和配置 MCP 允许访问的连接及执行权限。
- 数据迁移尚未完成或权限尚未设置时，保留原有拒绝执行行为；启动器仍能提供工作台入口与错误诊断。
- UI 操作与 Codex MCP 查询使用同一个后端和连接存储；后端返回权限拒绝时启动器不得改用直连绕过。
- 提供运行状态与停止服务工具；异常退出和启动失败显示可操作错误，禁止无上限重试。

## 生命周期与本地服务边界

- 仅监听 `127.0.0.1`，显式设置 `DBX_BIND_ADDR`；不能沿用 Web 版默认的所有网卡监听。
- 同一用户、同一插件数据目录复用一个服务；并发启动使用互斥，避免多个会话重复启动及端口冲突。
- 使用经过校验的运行状态、服务身份和版本判断是否复用；不能只通过端口占用或 PID 判断并终止进程。
- stdio 客户端断开只清理自己的 MCP 会话，不停止其他 Codex 会话或已打开工作台正在使用的服务。
- 本地服务允许独立于单次 MCP 会话存活；用户可通过停止工具关闭。退出/更新必须明确报告仍有活动任务时的状态，不能静默中断导入、写入或备份。
- 构建与安装不执行全局 Hook，不自动修改已有 Codex 全局 MCP 配置。

## 存储与认证

- 插件数据目录独立于安装缓存和桌面数据目录；macOS 默认使用用户应用数据目录中的 `com.dbx.codex`，其余平台使用对应用户应用数据目录。
- 数据目录保留 `dbx.db`、现有 Web 模式的加密密钥、驱动及必要运行状态。沿用 `ManagedDataDir`，不复制桌面钥匙串密钥。
- 插件更新不删除连接、历史或数据库文件。已有桌面连接通过现有加密配置导出/导入迁移，不直接覆盖或共享桌面数据库。
- MCP token 随机生成，保存在仅当前用户可读的文件中，使用现有 token-file 支持；不得写入插件清单、URL、日志或工具结果。
- 浏览器工作台保留现有密码与会话认证，不通过关闭密码保护实现免手动启动。
- Host/Origin 校验和现有生产保护继续生效；MCP 执行模式和 allowlist 在工作台管理，不在插件中扩大权限。

## 完整工作台与平台差异

保留官方 Web 版的全部现有工作台，不用少量 MCP 工具或简化页面代替。桌面专属交互必须有能力清单：可直接复用、需要适配、依赖驱动/系统能力三类分别列出。

重点核对连接创建、SQL 编辑/执行/取消、结果分页编辑、导入导出、SQLite 本地文件、Redis/MongoDB、驱动管理、配置迁移、历史与权限设置。文件操作沿用原有 Web 路径；缺失的桌面交互需要适配或明确呈现不可用原因，不能保留会静默失败的按钮。

桌面深链接工具不能继续尝试唤起桌面应用。Codex 插件提供工作台打开入口；打开指定表和显示查询结果需要接到 Web 工作台的导航能力。未完成这些适配前不能宣称桌面功能完全等价。

第三方 DBX 插件工具是否可在 Web 模式执行要单独核对，不能假设桌面插件运行能力随 MCP 自动获得。数据库专有驱动、JRE、数据库服务器和网络访问仍遵循原有实际依赖，不承诺安装包内含全部商业驱动。

## 验证与验收

1. 插件包可以从本地 marketplace 安装，路径不含开发机用户名，安装缓存迁移后仍可启动。
2. DBX 桌面应用未运行时，插件自动启动后台，Codex 内置面板打开完整工作台。
3. 在独立 SQLite 测试库创建连接；UI 与 MCP 读取同一表结构和数据，验证权限拒绝及允许访问范围。
4. SQL 查询、取消、结果编辑、导入导出和重启后恢复设置通过真实操作验收。
5. 并发启动不产生重复服务；端口冲突、服务崩溃、无效状态、缺失二进制返回明确错误。
6. 协议覆盖初始化、工具/资源发现、工具调用、错误、会话关闭和通知；保留 rmcp 的取消与会话行为。
7. 本地 HTTP 与 MCP 未认证访问被拒绝；非允许 Host/Origin 被拒绝；工具输出和日志不含认证 token。
8. 插件升级保留数据，停止服务不删除数据，不终止不属于本插件的进程。
9. 更新改动涉及的 Rust/前端测试，完成真实 Codex 面板验收；外部数据库仅将实际测试过的连接列为已验证。
