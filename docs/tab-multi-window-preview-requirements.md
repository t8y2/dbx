# dbx 多窗口标签页预览功能需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 多窗口标签页拖拽 |
| 功能类型 | 预览功能 |
| 文档状态 | 待确认 |
| 目标版本 | 待定 |

## 2. 背景与目标

当前 dbx 主要在单个窗口内通过多个标签页管理不同页面。为了提升多任务操作效率，需要支持类似 Chrome 的标签页拖拽能力：

- 任意标签页可以拖出并生成新的 dbx 窗口。
- 不同 dbx 窗口之间可以拖入、拖出标签页。
- 每个新窗口都具备完整的 dbx 标签页能力。
- 尽量复用现有标签页和页面逻辑，减少对原有代码的改动。

该功能属于预览功能，开发环境默认开启，同时提供用户开关。

## 3. 功能范围

### 3.1 窗口内标签页排序

用户在当前窗口标签栏内拖动标签页时：

1. 标签页进入拖拽状态。
2. 用户移动到目标位置后释放。
3. 标签页顺序发生变化。
4. 当前页面及其状态保持不变。

### 3.2 标签页拖出生成新窗口

用户将标签页拖出当前 dbx 窗口的标签栏或窗口区域时：

1. 创建一个新的 dbx 窗口。
2. 将被拖拽标签页移动到新窗口。
3. 原窗口移除该标签页。
4. 新窗口自动显示该标签页。

原窗口剩余标签页为零时，第一版暂不强制自动关闭原窗口，以降低额外逻辑和边界处理成本。

### 3.3 跨窗口拖入标签页

用户将标签页拖到另一个 dbx 窗口的标签栏时：

1. 目标标签栏显示可放置提示。
2. 用户释放鼠标后，标签页移动到目标窗口。
3. 源窗口移除该标签页。
4. 目标窗口新增该标签页并自动切换到该标签页。

### 3.4 新窗口继续使用标签页功能

新窗口必须支持原窗口已有的全部功能，不仅限于标签页管理。新窗口应当是一个功能完整的 dbx 实例，页面的增、删、改、查等操作均应与原窗口保持一致。

具体包括：

- 页面查询、列表查看和详情查看。
- 页面新增、创建或打开。
- 页面编辑和更新。
- 页面删除、关闭或移除。
- 页面刷新、重载和状态切换。
- 原窗口已有的筛选、排序、分页、导入、导出等页面功能（如适用）。
- 原窗口已有的权限校验、错误提示、加载状态和数据反馈。

同时，新窗口应支持与原窗口相同的标签页能力：

- 创建标签页。
- 关闭标签页。
- 切换标签页。
- 窗口内排序。
- 拖出标签页生成另一个窗口。
- 接收其他窗口拖入的标签页。

## 4. 新窗口 UI 要求

新窗口必须与原 dbx 窗口保持一致的 UI 风格，不得重新设计或随意修改界面。

具体要求：

- 复用原窗口的整体布局。
- 复用原有主题、颜色、字体和间距。
- 复用原有标签页、按钮、菜单和图标样式。
- 复用现有 UI 组件和交互规范。
- 不新增独立的新窗口视觉风格。

新窗口本质上应当是一个与原窗口一致的 dbx 实例，仅窗口承载的标签页集合不同。

## 5. 拖拽交互规则

### 5.1 拖拽判定

- 鼠标按下标签页但未明显移动时，仍按普通点击处理。
- 移动距离超过约 `5~10px` 后，进入拖拽状态。
- 拖动到当前窗口标签栏内：执行排序。
- 拖动到其他 dbx 窗口标签栏：执行跨窗口移动。
- 拖出所有 dbx 窗口可识别区域：创建新窗口。

### 5.2 拖拽反馈

- 被拖拽标签页显示半透明或其他轻量反馈。
- 目标插入位置显示提示。
- 可接收标签页的目标窗口或标签栏显示高亮。
- 无效区域不允许放置。

## 6. 标签页状态要求

标签页移动后应尽量保持原状态，包括但不限于：

- 标签页唯一 ID。
- 页面类型或路由。
- 页面标题和图标。
- 页面参数。
- 页面加载状态。
- 可保留的页面内部状态。

实现时优先移动现有标签页对象或页面实例，避免重复创建页面和丢失状态。若现有架构无法直接移动页面实例，可保存必要状态后在目标窗口恢复。

## 6.1 页面功能一致性

新窗口中的页面功能必须与原窗口保持一致：

- 使用相同的页面组件、路由和数据请求逻辑。
- 使用相同的增删改查接口和业务校验规则。
- 使用相同的权限、登录态和错误处理逻辑。
- 不因为窗口来源不同而限制页面操作能力。
- 在一个窗口中的页面操作结果，应按现有机制同步到其他窗口；如果当前没有跨窗口实时同步机制，至少保证刷新后数据一致。

除标签页所属窗口发生变化外，不应改变页面的业务行为。

## 7. 预览功能开关

### 7.1 开关名称

建议设置项名称：

```text
启用多窗口标签页预览功能
```

可在名称旁标注“预览功能”。

### 7.2 默认状态

- 开发环境默认开启。
- 用户可以在设置中手动开启或关闭。
- 开关关闭后立即禁用多窗口标签页能力，或在重启 dbx 后生效，具体实现方式以现有设置机制为准。

### 7.3 关闭后的行为

关闭功能后：

- 禁止拖出标签页创建新窗口。
- 禁止标签页跨窗口拖入。
- 保留现有单窗口标签页的创建、关闭、切换和排序功能。
- 不影响原有页面和业务逻辑。

## 8. 实现约束

- 优先修改和复用现有标签页管理逻辑。
- 不修改具体业务页面的实现。
- 不改变现有数据接口和页面路由行为。
- 新增逻辑应尽量集中在窗口管理、标签页管理和拖拽处理部分。
- 第一版以功能正确和状态不丢失为主，不要求复杂动画。
- 不引入与现有 UI 不一致的新组件样式。

## 9. 暂不包含的功能

第一版暂不实现以下内容：

- 窗口布局保存与恢复。
- 标签页跨设备同步。
- 标签页分组和收藏。
- 多窗口快捷键体系。
- 跨应用拖拽。
- 复杂拖拽动画和高级窗口编排。

## 10. 验收标准

1. 在同一窗口内拖动标签页，可以调整标签页顺序。
2. 将任意标签页拖出窗口，可以生成新的 dbx 窗口。
3. 新窗口 UI 与原窗口保持一致，没有额外或不同的视觉风格。
4. 新窗口可以正常创建、关闭、切换、排序和拖拽标签页。
5. 新窗口中的页面支持原窗口已有的全部增删改查功能及相关页面操作。
6. 新窗口使用与原窗口一致的路由、组件、数据请求、权限和错误处理逻辑。
7. 标签页可以从一个 dbx 窗口拖入另一个 dbx 窗口。
8. 标签页移动后不会产生重复标签页，页面状态尽量保持不变。
9. 开发环境默认开启该预览功能。
10. 用户关闭该功能后，原有单窗口标签页功能仍然正常。
11. 用户重新开启该功能后，多窗口拖拽能力恢复正常。

## 11. 待确认事项

- 原窗口在标签页全部移出后是否自动关闭：第一版建议不自动关闭。
- 预览功能开关修改后是立即生效还是重启后生效：建议优先复用现有设置机制。
- 标签页状态无法跨窗口直接转移时，允许按必要状态重新加载页面。

确认本需求文档后，再进入代码结构分析和实现方案设计阶段。

## 12. 已知问题：最大化/全屏窗口遮挡目标窗口

**状态：暂缓处理。**

### 复现

1. 打开 A、B 两个 DBX 窗口。
2. 将 A 最大化或全屏，使 B 被 A 遮挡。
3. 从 A 拖动标签页，期望合并到 B。

### 当前限制

当前跨窗口传输在拖拽结束后才依据鼠标坐标查找目标窗口。A 覆盖 B 时，用户无法在拖拽期间看见或明确悬停 B；仅靠窗口矩形不能可靠判断被遮挡窗口是否是用户意图的目标。因此该场景可能退回到“新建窗口”。

### 后续方案

采用独立的原生拖拽会话：拖出最大化/全屏窗口时创建可跟随鼠标的临时标签预览窗口；经过候选 DBX 窗口时将其置前并显示插入提示；松手后再提交移动。不要在 HTML5 拖拽进行中直接切换源窗口的最大化/全屏状态，以免 WebView2 原生拖拽会话被中断。

### 验收条件

- A 最大化或全屏时，拖入可见的 B 后不新建窗口。
- A、B、C 多窗口往返拖动，标签只进入鼠标当前可见的目标窗口。
- 取消或目标窗口未就绪时，源标签和源窗口状态保持不变。
