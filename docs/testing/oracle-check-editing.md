# Oracle 与 OceanBase Oracle CHECK 编辑

关联 #11441，包含 O01 约束读取与共同编辑基础。Web、Tauri 和结构页均接入新增、编辑、删除与启用/验证状态操作。

## 表达式与状态

- 原始表达式用于预览、执行和恢复，保留多行内容、引号及字符串，不按逗号或分号粗略切分。
- 独立的边界扫描识别单双引号、Oracle q 引号、注释及括号，拒绝未闭合边界、外层括号逃逸和引号外的语句分隔符。标识符仍单独引用。
- 验证使用 `WHERE NOT (expression)` 查找违规行，保留 CHECK 对 NULL/UNKNOWN 的通过语义。NOVALIDATE 仅做表达式语法解析，不要求历史数据全部满足。
- 仅改变启用/验证状态时直接变更；表达式或名称变化需要删除重建，并保留原始定义、状态和 RELY 属性。
- 预览和执行前重检新约束名称。OceanBase 使用服务器字符集的 `LENGTHB` 检查 128 字节限制；Oracle 使用安全引用的只读列别名交由当前版本解析。名称超限或无法核实时阻断全部 DDL，不先删除旧约束。
- OceanBase 前后端均拒绝延迟约束选项。未知状态不填充默认真值。
- 对承担列 NOT NULL 属性的约束，提示到列编辑入口处理，避免当作普通 CHECK 重建后改变列元数据语义。
- 执行后读取实际状态与表达式。解析后的结构比较忽略无意义的空白、外层括号及 Oracle 普通标识符大小写规则，但保留带引号名称与运算优先级。无法确认等价时明确返回待核对状态，不宣称成功。
- 任一步失败后保留逐步错误；只有确定原约束与新约束均不存在时才显示恢复原定义的 SQL。不自动恢复或盲目重放。

## 验证与限制

已编写边界注入、合法字符串/注释、quoted 名称、多行表达式、NULL 语义、状态修改、违规数据、权限、部分失败、读回失败、添加/删除与过期预览的行为用例及界面用例。当前只做必要语法解析；这些用例尚未运行。

SQL 解析器不能覆盖的合法数据库表达式仍可提交预检与 DDL；若数据库改写表达式且无法证明读回等价，则返回未确认状态，需结合实库验收处理，不能以 DDL 无错误代替验收。

依据：[Oracle constraint](https://docs.oracle.com/en/database/oracle/oracle-database/18/sqlrf/constraint.html)、[OceanBase 4.2.5 ALTER TABLE](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001504123)。仍需统一进行 Oracle/OB 隔离实库、GUI、回归、类型检查、编译、双审及 CI。
